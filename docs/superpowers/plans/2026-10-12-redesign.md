# Witamed Redesign „Boisko” — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Przerobić wygląd wszystkich stron Witamed na spójny styl „Boisko” w barwach logo, z motywem jasnym/ciemnym, mobile-first, bez utraty żadnej funkcji.

**Architecture:** Tokeny kolorów/typografii jako zmienne CSS w `src/index.css` dla `:root[data-theme="dark"|"light"]`; każdy istniejący plik CSS i styl inline przechodzi na tokeny. Nowa nawigacja (górny pasek + dolny pasek na telefonie) zastępuje obecny `NavBar`. Strony przerabiane po kolei; po każdej użytkownik weryfikuje na lokalnym podglądzie.

**Tech Stack:** React 19, TypeScript, Vite, react-router-dom 6, TanStack Query, zwykły CSS, `@heroicons/react` (już zainstalowany), Google Fonts (Barlow Condensed, Inter).

**Spec:** `docs/superpowers/specs/2026-10-12-redesign-design.md`

## Global Constraints

- **Zero utraty funkcji** — każdy punkt „Inwentarza funkcji” ze spec musi działać po zmianach.
- Bez zmian w bazie, routingu (URL-e bez zmian), zapytaniach Supabase; jedyne zmiany logiki: szybka obecność na głównej + `?redirect=` w logowaniu.
- Bez nowych bibliotek UI / CSS-frameworków.
- Paleta (spec): zielony `#6DB22A`, niebieski `#23609C`, żółty `#E3B23C`; ciemny: tło `#0B1622`, karta `#13243A`, tekst `#E8EEF4`, drugorzędny `#8CA0B5`, etykiety `#7FC241`; jasny: tło `#F2F5F8`, karta `#FFFFFF`+cień, tekst `#0B1622`, drugorzędny `#5B6B7C`, etykiety `#4E8A1A`, aktywna zakładka `#23609C`. Kontrast tekstu ≥ WCAG AA.
- Fonty: nagłówki Barlow Condensed 600–800 uppercase; tekst Inter 400–700.
- Motyw: domyślnie `prefers-color-scheme`, zapamiętany w `localStorage` pod kluczem `witamed-theme`, ustawiany przed renderem w `index.html`.
- Żadnych kolorów wpisanych na sztywno w CSS ani w `style={{}}` w TSX poza definicją tokenów.
- Mobile: brak poziomego scrolla strony (wyjątek: owinięte tabele statystyk), cele dotyku ≥ 44px.
- Teksty UI po polsku.
- **Nie pushować.** Commit lokalny po każdym zadaniu zaakceptowanym przez użytkownika.

## Review Focus

- Jasny motyw: tekst nieczytelny przez pozostawione `#fff` / `rgba(255,255,255,…)` w CSS lub inline → każde zadanie kończy się `grep` na te wartości w swoich plikach (wynik pusty).
- Dolny pasek zasłania treść / przyciski na dole strony (np. „Zapisz” w formularzach, modale) → `padding-bottom` na `main` = wysokość paska + `env(safe-area-inset-bottom)`; modale nad paskiem (z-index). Sprawdzane w zadaniu 1 i przy każdej stronie z modalem.
- Szerokie tabele (Statystyki, statystyki meczu, panel admina) na 375 px rozpychają stronę → wrapper `overflow-x:auto`; sprawdzenie `document.documentElement.scrollWidth <= 375` w każdym zadaniu z tabelą.
- Open redirect w logowaniu (`?redirect=https://evil`) → akceptowane tylko ścieżki zaczynające się od `/` i nie od `//` (zadanie 7).
- Mignięcie złego motywu przy przeładowaniu oraz brak `localStorage` (tryb prywatny) → skrypt w `index.html` w `try/catch`, fallback do `prefers-color-scheme` (zadanie 1).

## Weryfikacja (wspólna dla każdego zadania)

Projekt nie ma frameworka testowego; spec definiuje weryfikację jako:
1. `npx tsc -b` → brak błędów.
2. Przeglądarka (`$HOME/.claude/skills/gstack/browse/dist/browse.exe`, dev server `http://localhost:5173`): strona w motywie ciemnym i jasnym (`localStorage.setItem('witamed-theme', …)` + reload), viewport 375×812 i 1440×900; zrzuty pokazane użytkownikowi; `console --errors` bez nowych błędów (poza ostrzeżeniami React Router).
3. `scrollWidth` strony ≤ szerokości viewportu.
4. Przeklikanie funkcji strony z Inwentarza. Akcje zapisu testować tylko na danych testowych utworzonych na tę chwilę i usuniętych po teście (baza jest produkcyjna). Zalogowane widoki weryfikuje użytkownik (agent nie wpisuje haseł).
5. Użytkownik akceptuje → commit lokalny.
